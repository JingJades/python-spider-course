本章目标：熟练使用 Python 最流行的 HTTP 库 requests，掌握 GET/POST 请求、请求头伪装、Cookie 与 Session 会话管理，能应对 80% 的日常抓取需求。

requests 是第三方库，先确认已安装：pip install requests

第4课：GET请求与参数传递

4.1 最基本的 GET 请求

import requests

response = requests.get('https://httpbin.org/get')
print(response.status_code)   # 状态码
print(response.text)          # 响应内容（字符串）

📌 httpbin.org 是一个专门用于测试 HTTP 请求的演示网站，它会把你发送的请求信息原样返回，非常适合练习。如果网络环境无法访问，可以把示例中的地址换成任意可访问的网站，学习方法不变。

4.2 Response 对象的常用属性

属性/方法 作用
response.status_code 状态码，如 200
response.text 响应内容（自动解码为字符串）
response.content 响应内容（二进制，下载图片/文件用它）
response.headers 响应头（字典）
response.url 最终实际访问的网址（重定向后会变）
response.json() 当返回的是 JSON 数据时，直接转成 Python 字典

.text 和 .content 的区别是高频考点：

  • 抓网页源码 → 用 .text（字符串，方便解析）
  • 下载图片、视频、文件 → 用 .content（二进制，直接写文件）

4.3 携带查询参数：params

想搜索或翻页时，不要手动拼接 URL，用 params 参数更安全优雅：

import requests

# 等价于访问 https://httpbin.org/get?keyword=python&page=2
params = {
    'keyword': 'python',
    'page': 2
}
response = requests.get('https://httpbin.org/get', params=params)
print(response.url)  # 查看最终拼接好的网址

为什么推荐 params 而不是自己拼字符串？

  1. 参数中的中文、空格、& 等符号会被自动编码，手动拼接容易出错；
  2. 代码更清晰，改参数只改字典。

4.4 处理 JSON 数据

很多现代网站的数据接口直接返回 JSON（一种结构化的数据格式），requests 可以一键转成 Python 字典：

import requests

response = requests.get('https://httpbin.org/get', params={'name': '小明'})
data = response.json()          # JSON → Python 字典
print(type(data))               # <class 'dict'>
print(data['args'])             # 取出参数部分：{'name': '小明'}

判断标准：如果 response.text 开头是 {"... 或 [{...，基本是 JSON，用 .json()；如果开头是 <!DOCTYPE html> 或 <html，是网页源码，用第四章的 BeautifulSoup 解析。

4.5 设置超时时间

网站可能卡顿或无响应，一定要给请求加超时，否则程序会永远傻等：

import requests

try:
    response = requests.get('https://httpbin.org/get', timeout=5)  # 最多等5秒
    print(response.status_code)
except requests.exceptions.Timeout:
    print('请求超时，跳过这个网址')
except requests.exceptions.RequestException as e:
    print(f'请求出错: {e}')

📝 本课练习

  1. 用 params 构造一个请求，模拟在搜索引擎搜索「Python 教程」，打印最终 URL。
  2. 写代码请求一个接口，判断状态码是否为 200，是则打印内容，否则打印「请求失败，状态码：xxx」。
  3. 下载一张网络图片（如 https://httpbin.org/image/png），思考应该用 .text 还是 .content，并说出理由。

第5课：POST请求与表单提交

5.1 GET 与 POST 的区别

对比项 GET POST
用途 获取数据 提交数据
参数位置 拼在 URL 里（看得见） 放在请求体里（URL 里看不见）
典型场景 打开网页、搜索、翻页 登录、注册、发表评论、上传文件

5.2 发送 POST 请求：data

模拟表单提交，用 data 参数传递字典：

import requests

data = {
    'username': 'xiaoming',
    'password': '123456'
}
response = requests.post('https://httpbin.org/post', data=data)
result = response.json()
print(result['form'])   # {'username': 'xiaoming', 'password': '123456'}

5.3 发送 JSON 格式的 POST 数据

有些接口要求提交 JSON 而不是表单，用 json 参数：

import requests

payload = {'name': '小明', 'age': 25, 'hobbies': ['篮球', '编程']}
response = requests.post('https://httpbin.org/post', json=payload)
print(response.json()['json'])   # 服务器收到的 JSON 数据

data vs json 怎么选？ 打开 F12 开发者工具看真实浏览器请求：请求体是 username=xx&password=xx 形式用 data；是 {"username":"xx"} 形式用 json。

5.4 实战思路：模拟登录的一般套路

模拟登录是 POST 最典型的应用，通用思路：

  1. 在浏览器手动登录一次，用 F12 抓包，找到登录请求（通常是 POST）；
  2. 记录它的 URL、请求参数（账号、密码字段名，可能还有验证码/token）；
  3. 用 requests.post() 照抄参数发送；
  4. 登录成功后保存 Cookie（下一课详讲），后续请求都带着它。
import requests

login_url = 'https://httpbin.org/post'  # 实际项目换成真实登录接口
data = {
    'username': 'my_account',
    'password': 'my_password'
}
response = requests.post(login_url, data=data)
if response.status_code == 200:
    print('登录请求发送成功，检查返回内容判断是否登录成功')

📝 本课练习

  1. 向 https://httpbin.org/post 分别用 data 和 json 各发一次 POST 请求，对比返回结果中 form 和 json 字段的差异。
  2. 找一个你常用的网站，用 F12 观察它的登录请求是 POST 还是 GET？参数有哪些字段？（只观察，不要真的提交）

第6课：请求头设置与身份伪装

6.1 为什么需要伪装

很多网站有「反爬虫」机制：检查请求的 User-Agent。Python 的 requests 默认 User-Agent 是 python-requests/2.x.x，等于脑门上贴着「我是机器人」，很容易被 403 拒绝。

对策：把请求头伪装成真实浏览器。

6.2 设置 User-Agent

先去 F12 复制自己浏览器的 User-Agent，然后放进 headers 字典：

import requests

headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                  'AppleWebKit/537.36 (KHTML, like Gecko) '
                  'Chrome/120.0.0.0 Safari/537.36'
}
response = requests.get('https://httpbin.org/headers', headers=headers)
print(response.json())   # 可以看到服务器收到的 User-Agent 已经变成浏览器的了

技巧：https://httpbin.org/headers 会原样返回你发送的请求头，是验证伪装是否成功的好工具。

6.3 常用请求头字段

字段 作用 什么时候需要加
User-Agent 声明浏览器身份 几乎每次都要
Referer 声明来源页面 防盗链的图片/视频下载
Cookie 登录凭证 需要登录才能看的页面
Accept-Language 语言偏好 避免返回英文版页面 
headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0',
    'Referer': 'https://www.example.com/',
    'Accept-Language': 'zh-CN,zh;q=0.9'
}

6.4 一个带完整伪装的请求模板

建议把下面这段代码存为自己的「爬虫起手模板」：

import requests

def fetch(url):
    """带伪装和异常处理的通用请求函数"""
    headers = {
        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                      'AppleWebKit/537.36 (KHTML, like Gecko) '
                      'Chrome/120.0.0.0 Safari/537.36'
    }
    try:
        response = requests.get(url, headers=headers, timeout=10)
        response.raise_for_status()   # 状态码不是2xx时主动抛异常
        return response
    except requests.exceptions.RequestException as e:
        print(f'抓取失败 {url}: {e}')
        return None

resp = fetch('https://example.com')
if resp:
    print(resp.text[:200])

response.raise_for_status() 是好习惯：状态码 4xx/5xx 时直接报错，避免拿着错误页面去解析，排查半天才发现根本没抓到数据。

📝 本课练习

  1. 从 F12 复制你自己浏览器的 User-Agent，请求 https://httpbin.org/headers 验证伪装效果。
  2. 对比实验：不加 User-Agent 和加 User-Agent 分别请求同一个页面，观察返回内容或状态码的差异。

第7课：Cookie与Session会话管理

7.1 为什么需要 Cookie

HTTP 协议本身是「健忘」的：服务器默认不记得你上一次请求是谁。登录成功后，服务器会发给你一个 Cookie（一小段身份凭证），之后你每次请求都带上它，服务器就知道「哦，是刚才登录过的那位」。

爬虫要抓取「登录后才能看」的内容，就必须正确处理 Cookie。

7.2 从响应中读取 Cookie

import requests

response = requests.get('https://httpbin.org/cookies/set/name/xiaoming')
print(response.cookies)              # CookieJar 对象
print(dict(response.cookies))        # 转成字典查看：{'name': 'xiaoming'}

7.3 手动携带 Cookie 请求

适合 Cookie 已经从浏览器复制的场景（F12 → 请求头 → Cookie）：

import requests

headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0'
}
cookies = {
    'session_id': 'abc123xyz',   # 从浏览器复制的登录凭证
}
response = requests.get('https://httpbin.org/cookies',
                        headers=headers, cookies=cookies)
print(response.json())

7.4 Session：自动管理 Cookie 的「连续对话」

如果一个网站是「先 POST 登录 → 再 GET 个人页面」两步操作，手动传递 Cookie 很麻烦。Session 对象会自动记住并携带 Cookie，相当于在代码里开了一个「不会失忆的浏览器」：

import requests

# 创建会话对象
session = requests.Session()
session.headers.update({
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0'
})

# 第1步：登录（服务器返回的 Cookie 会被 session 自动保存）
session.post('https://httpbin.org/cookies/set/token/my_login_token')

# 第2步：访问需要登录的页面（session 自动带上上一步的 Cookie）
response = session.get('https://httpbin.org/cookies')
print(response.json())   # {'cookies': {'token': 'my_login_token'}}

普通 requests 与 Session 的区别：每次 requests.get() 都是一次「全新访问」，互不认识；session.get() 是「连续对话」，Cookie 自动继承。模拟登录场景一律用 Session。

7.5 本章综合小练习：带登录态的抓取流程

import requests

session = requests.Session()
session.headers.update({
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0'
})

# 1. 登录
login_resp = session.post('https://httpbin.org/post',
                          data={'username': 'demo', 'password': 'demo123'})
print('登录请求状态:', login_resp.status_code)

# 2. 用同一个 session 继续访问（Cookie 自动携带）
profile_resp = session.get('https://httpbin.org/get', timeout=10)
print('后续访问状态:', profile_resp.status_code)

📝 本课练习

  1. 用自己的话解释：为什么模拟登录必须用 Session 而不是单独的 requests？
  2. 在浏览器登录一个网站后，用 F12 找到请求头里的 Cookie 字段，观察它的格式（key=value; key=value）。
  3. 思考：Cookie 过期了会发生什么？程序应该如何应对？

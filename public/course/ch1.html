第1课：什么是网络爬虫

1.1 从一个生活场景说起

假设老师让你整理「过去一个月某新闻网站所有标题」，你有两种做法：

  • 人工做法：打开网站 → 复制标题 → 粘贴到 Excel → 翻页 → 重复几百次。可能需要一整天。
  • 爬虫做法：写一段几十行的 Python 程序，让它自动完成「打开网页 → 读取标题 → 写入文件 → 自动翻页」。可能只需要几分钟。

网络爬虫（Web Crawler / Spider），就是一种按照一定规则，自动抓取互联网信息的程序。它模拟浏览器访问网页，把网页内容下载下来，再从中提取我们需要的数据。

1.2 爬虫能做什么

应用场景 具体例子
数据采集 电商商品价格监控、招聘网站职位汇总
数据分析 抓取新闻/评论做舆情分析、行业报告
内容聚合 搜索引擎（百度、Google 的核心就是巨型爬虫）
自动化 自动签到、自动监控网页更新并提醒

1.3 爬虫的基本工作流程

所有爬虫，无论简单还是复杂，都遵循同一个四步流程：

┌────────────┐    ┌────────────┐    ┌────────────┐    ┌────────────┐
│ 1.发送请求  │ →  │ 2.获取响应  │ →  │ 3.解析数据  │ →  │ 4.存储数据  │
│ (requests) │    │ (网页HTML) │    │(BS4/正则)  │    │(文件/数据库)│
└────────────┘    └────────────┘    └────────────┘    └────────────┘

对照课程章节看，你会发现整个课程就是沿着这条主线展开的：

  • 第二、三章（requests / urllib）解决 第 1、2 步；
  • 第四、五章（BeautifulSoup / 正则表达式）解决 第 3 步；
  • 第六章实战把 第 4 步 和全流程串起来。

1.4 你的第一个爬虫程序

先感受一下完整流程。下面这段代码只有 7 行，却能抓取一个网页的标题（先不用理解细节，后面章节会逐一拆解）：

import requests
from bs4 import BeautifulSoup

url = 'https://example.com'          # 1. 目标网址
response = requests.get(url)         # 2. 发送请求，获取网页内容
soup = BeautifulSoup(response.text, 'lxml')  # 3. 解析HTML
title = soup.find('title').get_text()        # 4. 提取标题文字
print(f'网页标题: {title}')

运行结果类似：

网页标题: Example Domain

第2课：Python爬虫技术架构

2.1 一个爬虫程序的四大模块

专业的爬虫程序通常由四个模块组成，本课程先掌握前三个，第四个了解即可：

① 请求模块（下载器） 负责和网站服务器「对话」：把请求发出去，把网页内容收回来。 - 本课程主力工具：requests（第三方库，简单易用，第二章） - 备选工具：urllib（Python 自带，无需安装，第三章）

② 解析模块（解析器） 下载回来的网页是一整坨 HTML 文本，解析模块负责像「剪刀」一样把需要的数据剪出来。 - BeautifulSoup：把 HTML 变成可操作的对象树（第四章） - re 正则表达式：用模式匹配直接从文本中捞出数据（第五章）

③ 数据存储模块 提取出来的数据要落地保存：TXT/CSV 文件、Excel、数据库（MySQL、MongoDB）等（第六章实战会用到文件存储）。

④ 调度模块（了解） 控制「先爬哪个页面、再爬哪个页面、爬多快、失败了重试」。大型框架如 Scrapy 内置了调度器，本课程用手动循环实现简单调度。

2.2 为什么是 Python

对比项 Python 其他语言常见情况
上手难度 语法接近英语，初学者友好 Java/Go 配置和语法更繁琐

2.3 同步与并发（概念了解）

  • 同步爬取：爬完一个页面再爬下一个。简单但慢，本课程入门阶段使用。
  • 并发爬取：同时爬多个页面（多线程/协程）。速度快几十倍，是进阶内容。

入门阶段记住一句话：先把「能跑」写出来，再考虑「跑得快」。

第3课：HTTP协议基础

这是全课程最重要的一节概念课。爬虫的本质就是「代替浏览器发 HTTP 请求」，不懂 HTTP，后面遇到反爬、登录、乱码都会一头雾水。

3.1 浏览器访问网页时发生了什么

当你在浏览器输入网址按下回车，实际发生了一次「一问一答」：

你的电脑（客户端）                网站服务器
      │                                │
      │ ──── HTTP 请求(Request) ────▶  │   「我要 https://example.com 这个页面」
      │                                │
      │ ◀─── HTTP 响应(Response) ────  │   「给你，这是网页的HTML内容」
      │                                │

爬虫程序就是用代码模拟左边这个角色：自己构造请求发出去，再接收并处理响应。

3.2 URL 的结构

URL（网址）是请求的目标地址，拆开看：

https://www.example.com:443/path/to/page?id=100&page=2#top
└─┬─┘   └──────┬──────┘└┬┘└──────┬─────┘└──────┬──────┘└┬┘
 协议         域名      端口      路径          查询参数   锚点

爬虫最常打交道的是查询参数（? 后面的部分）。很多网站的翻页就是改参数：page=1、page=2、page=3……掌握这一点，就掌握了「自动翻页」的钥匙。

3.3 请求（Request）的组成

一次 HTTP 请求包含：

  1. 请求方法：最常见两种
  2. GET：向服务器要数据（打开网页、搜索）
  3. POST：向服务器提交数据（登录、提交表单）
  4. 请求头（Headers）：附加信息，其中最重要的是：
  5. User-Agent：告诉服务器「我是谁」（什么浏览器、什么系统）。很多网站会拒绝没有 User-Agent 的「裸奔」请求，所以爬虫通常要伪装它。
  6. Cookie：登录状态的「通行证」
  7. Referer：从哪个页面跳转过来的
  8. 请求体（Body）：POST 请求携带的数据，GET 请求一般没有。

3.4 响应（Response）的组成

服务器返回的内容包含：

  1. 状态码：本次请求的结果，常见状态码务必背下来：
状态码 含义 爬虫视角的解读
200 成功 一切正常，拿到数据了
301/302 重定向 网址搬家了，requests 会自动跟过去
403 禁止访问 被网站识别并拒绝了，检查 User-Agent
404 页面不存在 网址错了或页面已删除
500 服务器错误 网站自己出问题了，稍后再试
  1. 响应头：服务器的信息（内容类型、编码等）。
  2. 响应体：真正的内容——HTML 源码、JSON 数据、图片二进制等。

3.5 用浏览器「偷看」HTTP 请求

一个必须掌握的技能——开发者工具：

  1. 用 Chrome/Edge 打开任意网页；
  2. 按 F12 打开开发者工具，切换到 Network（网络） 面板；
  3. 刷新页面，会看到密密麻麻的请求列表；
  4. 点击第一个请求，就能看到它的 Headers（请求头/响应头/状态码） 和 Response（响应内容）。

以后写爬虫前，先用开发者工具看清楚浏览器发的是什么请求，再用代码照抄，这是爬虫工程师的日常姿势。

3.6 动手：用代码打印一次完整的请求与响应

import requests

response = requests.get('https://example.com')

print('状态码:', response.status_code)          # 200 表示成功
print('响应头中的内容类型:', response.headers.get('Content-Type'))
print('网页前100个字符:')
print(response.text[:100])
